# 006 — Hosted クレジットと資金決済法（調査メモ）

日付: 2026-07-29  
地位: **法律意見ではない。実装と並行調査。公開前に専門家確認必須。**  
北極星: [004](./004-hosted-ux-north-star.md) Hosted UX

## 1. いまの仮説（専門家未確認）

Presence が「分（または秒）クレジット」を販売し、自サービス（Live 通話）の対価にだけ使えるようにする場合、  
**自家型前払式支払手段（資金決済法）に該当しうる**、というのが協会・財務局資料から読める一般論。

| 論点 | メモ（要確認） |
|---|---|
| 自家型 vs 第三者型 | 自サービス内のみなら自家型寄り。第三者の店で使えると第三者型（事前登録） |
| 届出のきっかけ | 基準日（3/31・9/30）の**未使用残高合計が 1,000 万円超**で自家型の届出等が論点（日本資金決済業協会 FAQ 等） |
| 供託 | 届出後、未使用残高の 1/2 以上の発行保証金（または保全契約）などが論点 |
| 資金移動業 | 「A から預かり B に送金」型ではない建付けなら、通常は前払式側の議論が主。ただし表現次第 |

出典の入口（公式・準公式）:
- 日本資金決済業協会「前払式支払手段発行業の概要 / FAQ」
- 関東財務局「前払式支払手段関係」

## 2. 実装で先に入れておく順守寄り設計

法律確定前でも、後から届出しやすい形にしておく:

1. **自家型に閉じる** — クレジットは Presence の音声/テキスト役務にのみ使用  
2. **有償と無償を分離** — Free お試し秒は `grant_type=promo`、購入分は `purchase`（帳簿上分けられる）  
3. **残高台帳** — user / 増減 / 理由 / 時刻を残す（管理帳の種）  
4. **表示** — 名称、利用範囲、有効期限、残高確認、問い合わせ（UI にプレースホルダ）  
5. **有効期限** — 購入分に `expiresAt`（例: 180 日）。規約と一致させる  
6. **返金方針** — 「原則返金不可（法令に基づく場合を除く）」を規約に書く（文言は弁護士レビュー）  
7. **未使用残高モニタ** — 管理 API で合計未使用を見られるようにする（1,000 万円警戒）  
8. **「現金」「送金」「ウォレット送金」表現禁止**

## 3. 実装スコープ（この PR）

- Hosted モード: 運営キーで ephemeral 発行＋残高メータ  
- Stripe でクレジットパック購入  
- BYOK は設定の「上級者」に残す  
- 届出・供託・顧問契約そのものはコード外（人間）

## 4. 公開ゲート（人間）

1. 弁護士（資金決済）に「自家型該当性・表示・有効期限・返金」を確認  
2. 問い合わせ先・商号の確定  
3. 未使用残高 1,000 万円超えない運営方針（価格・発行上限）  
4. Stripe / 運営 API キーを本番 env に置く承認
